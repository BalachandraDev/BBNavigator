# FlowMind security notes

What is protected, how, and what is *not* covered. Written for the people who will run and audit the system.

## Who can do what

| Caller | How they sign in | Can |
|---|---|---|
| **Platform admin** | `Auth:PlatformAdminKey` | Manage companies (tenants): create, **view or reset a company's sign-in key**, **disable/enable** its access, **delete** it with all its data. Cannot read any company's documents, answers or conversations. Disabled when the key is empty. |
| **Company admin** | Company ID + company API key (shown once at creation) | Upload/delete documents, review and approve knowledge, issue/revoke user keys, see AI usage, chat. |
| **Company user** | Company ID + a *user access key* issued by the company admin | Read **approved** knowledge and chat. Nothing else. Sees only their own conversations. |

Every endpoint declares its rule. A test fails the build if any endpoint lacks one, and pins the list of anonymous endpoints to
`auth/token`, `system/info`, `health/live`, `health/ready`.

## Controls

**Tenant isolation**
- The tenant comes only from the signed token, never from request data.
- EF Core global query filters on every tenant-owned table, plus a write guard that refuses saving another tenant's row.
- Vector search always filters `tenant_id` and `application_id` in SQL (parameterised); search/delete helpers have no "no tenant" overload.
- Storage paths are generated by the server (`tenant/document/version`), never from a file name.

**Authentication**
- Keys are 256-bit random. **Sign-in always verifies a SHA-256 hash.** For company keys (not user keys) the server also keeps a recoverable copy, encrypted with AES-256-GCM under the separate server secret `Security:SecretsKey`, so the platform admin can view it again. A stolen database alone does not reveal keys; stealing the database **and** the server secret does. Every view, reset, disable, enable and delete is audited. Comparison is constant-time. Failed sign-ins return one generic error (no user/tenant enumeration) and are rate-limited (10/min/IP) and audited.
- JWT: HMAC-SHA256, issuer/audience/lifetime validated, 60-minute default. On every request the token's company must still be active and, for users, the key must not be revoked (cached ≤15 s), so **revocation takes effect within ~15 seconds**.
- Browser holds the token in `sessionStorage` only. No AI key or secret is ever sent to or stored in the browser.

**AI safety**
- Documents, questions and AI output are untrusted. Chat excerpts are delimited and the model is told to ignore instructions inside them; answers must cite a real source or become a fixed "not documented" reply.
- AI output is stored and shown as plain text. It never becomes SQL, a command, a URL fetched by the server, or HTML. (The UI has no `innerHTML`; a test enforces it.)
- Only **approved** documents are searchable; users only see **approved** knowledge.

**Cost and abuse**
- Every provider has a hard daily cap enforced by FlowMind itself, default **0 = off**. When a cap or the provider's free quota is reached the feature pauses; nothing falls back to a paid model.
- Chat/search are limited per user (default 15/min) and globally per IP (120/min).

**Uploads**
- Allow-list PDF/DOCX/TXT, magic-byte check, 25 MB cap, SHA-256 de-duplication, DOCX unpack limit (100 MB / 5,000 parts) against zip bombs, page cap (500).

**Browser/transport**
- Strict CSP (`script-src 'self'`, no inline script/style, no third-party origins, `frame-ancestors 'none'`), `nosniff`, `no-referrer`, `X-Frame-Options: DENY`; `Cache-Control: no-store` on all `/api` responses.
- Outside Development: HTTPS redirect + HSTS (`Security:RequireHttps`), Swagger off (`Swagger:Enabled`), and **startup refuses** development secrets, the LocalDB connection or the dev DB password (`ProductionGuards`).

**Auditing** — sign-ins (success/fail), tenant/application/key creation and revocation, uploads, reviews, approvals, retries, deletions → `AuditLogs` (actor, IP, entity).

## Known limits (be honest about these)

- **Shared company admin key.** All admins of a company share one key; audit shows `tenant:<id>`, not a person. Per-person admin accounts are not implemented. The platform admin can view this key (by design, audited); if that is not acceptable for your organisation, leave `Security:SecretsKey` empty in a deployment where nothing recoverable should be stored (the key is then shown only at creation or reset).
- **No MFA / SSO.** Keys are bearer secrets. Treat them like passwords; rotate a company key with **Reset key** on the platform admin screen (the old key stops at once and company-admin sessions opened with it end) and revoke user keys on the Access page. Companies created before key viewing existed have no stored key: use Reset key once.
- **Revocation window** up to 15 s; an in-flight request finishes.
- **External AI providers see document text.** Gemini, Cloudflare, Groq and Mistral receive document excerpts. Free tiers may use data for training. Use synthetic or approved-for-sharing documents until your company has accepted each provider's terms.
- **Rate limits are per process.** With several web servers each keeps its own counters.
- **Behind a reverse proxy** the client IP is the proxy's unless forwarded headers are configured — then IP-based limits would share one bucket. In-process IIS hosting sees the real client IP.
- **Prompt injection cannot be fully eliminated.** Mitigated by approval-only content, delimiting, citation enforcement and text-only output; a malicious *approved* document could still mislead answers, which is why review exists.
- **Duplicate-upload race**: two identical uploads at the same instant can both be stored (harmless).
- **Backups and retention** are the operator's job (see OPERATIONS.md). Deleting a document purges its file, text and vectors; metadata and audit rows are kept. **Deleting a company** purges all of its rows, search vectors and files (usage counters and audit rows are kept on purpose); it does not reach into backups you already took, and a job already running in the worker may need a moment to stop.
- **Changing `Security:SecretsKey`** makes stored company keys unreadable (Show login then asks you to Reset key). Back the secret up with the other secrets.

## Reporting / reviewing
Run `dotnet list package --vulnerable --include-transitive` on every release (currently clean) and `dotnet test` (includes the authorization matrix, tenant isolation, CSP/no-innerHTML and production-guard tests).
